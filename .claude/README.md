# .claude/settings.json について

JSON にはコメントが書けないので、説明はこちらに分けています。

## これは何？

Claude Code に「このファイルは開かないで」と伝える設定です。
講座で言う**3重ロックの3つ目**にあたります。

1. `.env` に置く（コードに直接書かない）
2. `.gitignore` に入れる（GitHub に送らない）
3. **この設定で読み取りを拒否する（AI にも渡さない）** ← ここ

## 置き場所

作業フォルダの直下に `.claude` というフォルダを作って、その中に置きます。

```
claude-workshop/
├── .claude/
│   └── settings.json    ← これ
├── .env
└── CLAUDE.md
```

`.claude/settings.json` はプロジェクトの設定なので、
チームで共有する前提のファイルです。GitHub に送っても構いません。
**値の入った `.env` とは扱いが違います。**

## 書いてある内容

```
"Read(./.env)"          .env を読ませない
"Read(./.env.*)"        .env.local などの派生も読ませない
"Read(./secrets/**)"    secrets フォルダの中身すべて
"Read(./**/*.key)"      拡張子が .key のファイルすべて
"Read(./credentials.json)"
"Bash(cat ./.env)"      ターミナル経由の cat も塞ぐ
"Bash(type ./.env)"     Windows の type コマンドも塞ぐ
```

`Read` の指定は、読み取りだけでなく編集・書き込みも止まります。

## これで完全に安全、ではありません

**ここが大事なところです。**

`Read` の拒否で止まるのは、Claude Code のファイル読み取り機能です。
ターミナルから中身を開く経路は、コマンドの書き方が無数にあるため、
すべてを列挙して塞ぎきることはできません。

上の `Bash(cat ./.env)` なども、代表的な書き方を塞いでいるだけです。

だから**1つで守ろうとせず、3つ重ねます。**
どれか1つが破られても、残りが効いている状態にしておく。
それが「3重ロック」という言い方をしている理由です。

## ついでに気をつけること

- 自分で書いたスクリプトがキーを画面に表示してしまうことがあります
- エラーメッセージにキーが混ざることがあります
- エラーを誰かに見せるときは、キーが写っていないか確認してください
